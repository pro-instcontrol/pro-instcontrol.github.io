13. Case-Based Reasoning for Safety Evaluation 13. Suy luận dựa trên tình huống trong đánh giá an toàn

When problem solving is based on experience which is difficult to define as explicit rules, it is possible to apply case-based reasoning (CBR). CBR uses directly the solutions of old problems to solve new problems. The functional steps in CBR are (Gonzalez and Dankel, 1993):

  1. New problem presentation.
  2. Retrieval of the most similar cases from the case-base.
  3. Adaptation of the most similar solutions for generating a solution for the current problem.
  4. Validation of the current solution.
  5. Learning from the problem cases by adding the verified solution into the case-base.

A data table of a case-base can be divided into input and output sections: the input parameters are retrieval parameters and the output parameters are design specification parameters. The problem is characterized as input data to the system; in the retrieval phase the set of retrieval-parameter values of all cases in the case-base is compared to the input data; the most similar cases are then selected and ranked based on the comparison.

In the case of string data types the suitability is simply:

((7))Xi = Ci,j ⇒ Yi,j = 1
((8))Xi ≠ Ci,j ⇒ Yi,j = 0

where Xi is the input value of parameter i, Ci,j the value of parameter i of case j, and Yi,j the suitability of parameter i for case j. The quality of reasoning increases if the importance of the selection parameters can be altered: the user should determine the importances of the selection parameters for the topic under study. The weighted suitability Rij can be expressed:

((9))Rij = Wi Yi,j

where Wi is the weight factor of selection parameter i evaluated by the user. The overall suitability can be calculated for case j based on the number of parameters N and the parametric suitabilities Rij:

((10))SR = Σi=1N Ri,j / N

Case-based reasoning has earlier been used, for instance, for equipment design. Koiranen and Hurme (1997) used CBR for fluid-mixer design and for the selection of shell-and-tube heat exchangers, including an estimation of design quality for case retrieval beside technical factors. Chung and Jefferson (1997) combined the IChemE Accident Database (Smith et al., 1997) with CBR to create an automatic data retrieval for designers' and operators' use; they intend to develop an intelligent system which takes, for example, the term "electrical equipment failure", works out all the related terms and retrieves the relevant information automatically, integrated with the computer tools of designers, operators and maintenance engineers. The aim of their system is to find all relevant causes of past accidents to improve processes, whereas our CBR system is intended for reasoning on the structure of a process and its favourable and unfavourable characteristics for preliminary process design; their database is an accident database, whereas ours contains also design recommendations; their system is developed for wider use — from plant designers and operators to maintenance teams — while ours is intended specifically for process designers.

13.1 Description of Prototype Application 13.1 Mô tả ứng dụng nguyên mẫu

The prototype CBR application has been implemented on an MS-Excel spreadsheet, organized on several sheets. A database of cases was created, consisting of accident cases collected from the literature (e.g. Lees (1996) and the Loss Prevention Bulletin) and of design recommendations; the application includes retrieval functions used to retrieve the most suitable cases from the database.

13.1.1 Input and Output Parameters 13.1.1 Tham số đầu vào và đầu ra

The scope of a database search is defined by using the categories process, subprocess, system, subsystem, equipment and detail as input parameters. This hierarchy is used to clarify the process structure and to make the use of process analogies more feasible in reasoning — e.g. a condenser has certain safety characteristics independent of the process it is located in. Beside the process structures, the input parameters include the raw materials and products and some reaction details; the importance of the parameters may be evaluated using weighting factors.

The output parameters contain the input parameters plus information on the safety characteristics of the process and information on accidents and their causes; specific design recommendations are included in the output. On accidents, the output describes:

  • what kind of incidents have happened;
  • what is the actual cause of the incident;
  • what are the contributing factors or circumstances;
  • how to improve the application for better safety.

All stored cases are validated on the basis of the Safe Process Structure Subindex; the validations are given for every case and included in the output. Further information is given as appendices, which describe the case in more detail.

13.1.2 Retrieval of Cases 13.1.2 Truy hồi tình huống

In this work the cases are stored on their own MS-Excel worksheets and copied onto a retrieval calculation sheet during the retrieval phase. All retrieval parameters are textual string parameters, so the comparison between the case-base and the input problem is simple: when the input value equals the case value the distance is 1, otherwise 0. The weighted suitability is calculated by Equation 9 with the weighting factors introduced by the user; the overall suitability by Equation 10. The cases are ranked according to their overall suitability and the five nearest cases are shown to the user on an output worksheet.

The retrieval of cases can be done in several steps: the first step is the evaluation of the process with the stored cases — this shows whether the process is safer or unsafer than the alternative processes; the second step is the safety evaluation of specific process systems, subsystems or pieces of equipment; the database contains improvement recommendations to avoid the same accidents happening again. The evaluation can be extended to the detailed level — even equipment details or safety valves can be checked at this level.

13.2 Case Study 13.2 Nghiên cứu tình huống

For the evaluation of the safe process structure of the acetic acid process (Ch. 12, Fig. 7), CBR database searches were done on two levels (Heikkilä et al., 1998): the first level was the acetic acid process as a whole; on the second level the reactor system was studied in more detail.

13.2.1 CBR on Process Level 13.2.1 CBR ở mức quá trình

First the acetic acid process was studied as a whole, to find out whether the alternative processes differ in safety at the conceptual (i.e. process) level. The search (Table 28) found cases for carbonylation and oxidation processes (Table 29). It can be seen that there have been explosions and fires on both types of plants. The explosion in the carbonylation plant was due to static electricity in the loading of a storage vessel — this type of explosion is not specific to carbonylation plants but is possible in many other processes. The fires and explosions in the oxidation plants were related to the chemicals present in that process — they are more likely to happen in such a plant than somewhere else. Thus, based on the information from this search, the carbonylation process can be considered safer than the oxidation process.

13.2.2 CBR on the Reactor System 13.2.2 CBR ở hệ lò phản ứng

In the second phase, searches were made on the system and subsystem level — needed for the comparison of process alternatives and for the design of the exothermic reactor and its heat-transfer systems. Carbonylation of methanol is an exothermic reaction, so only exothermal reactors were searched. The CBR search found two cases — general recommendations on the design of exothermic reactors with heat-transfer systems, shown in Figures 8 and 9.

The case in Figure 8 represents a reactor with two different cooling systems. In the not recommended case (right), the cooling system presents a feedback loop between a reactor heat rise and the rise in the coolant temperature, which should be avoided. On the left is the recommended system, where the coolant temperature does not depend on the reactor temperature.

The case in Figure 9 shows a heat-recovery system of a reactor. In the not recommended case (left), the feed to an exothermic reactor is heated by the product: a temperature rise in the reactor may lead to a temperature rise in the feed. The recommended case (right) is safer since the connection is broken — the heat transfer is done by generating and using medium-pressure steam.

13.2.3 Score of the Safe Process Structure Subindex 13.2.3 Điểm của chỉ số cấu trúc quá trình an toàn

From the reasoning on the process level we get score 2 (no data or neutral) for the carbonylation process, since the found case was not specific to this process. For the oxidation process we get score 5, since a major accident has taken place. For the recommended reactor system we can get scores 0 (recommended/standard) or 1 (sound engineering practice), depending on how we value these recommendations.

The final score of the Safe Process Structure Subindex for the carbonylation process would be 2 based on this limited reasoning, since the final score of IST is chosen on the basis of the worst case. Of course, in practice one should reason on all the systems and subsystems of the process; this case study was given only to represent the principle of CBR in reasoning the value of the Safe Process Structure Subindex.

Result: carbonylation IST = 2 (neutral) vs oxidation IST = 5 (major accident); the recommended reactor system scores 0–1. The final score on the worst-case basis = 2 for the acetic acid process within this limited reasoning.
